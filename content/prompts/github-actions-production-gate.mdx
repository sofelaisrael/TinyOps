**Context:** A force-push, bot commit, or merge side-effect triggers an unintended production deploy because the workflow deploys on every push to `main` without any protection.

**Goal:** Add a GitHub Actions environment gate with required reviewers so every production deploy pauses for human approval.

**Requirements:**
1. Explain GitHub Environments and their protection rules (required reviewers, wait timer, branch restrictions).
2. Add an `environment: production` field to the deploy job with the `needs:` dependency on build/test jobs.
3. Walk through creating the "production" environment in GitHub Settings → Environments → Environment protection rules.
4. Configure "Required reviewers" (1 or more people/teams) in the environment settings.
5. Show how to pass environment-level secrets and URL to the deploy step.
6. Cover the auto-approve case for trusted CI — use a deployment branch policy instead.
7. Include a fallback for orgs without Environments feature: use `github-script` action to post a check-run and wait for external approval.

**Output:** Provide a deployment workflow with an environment gate and the setup instructions for the GitHub environment configuration.
