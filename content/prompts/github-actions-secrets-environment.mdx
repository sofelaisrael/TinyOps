**Context:** A workflow runs successfully in one context but fails with auth errors in another. The secret is stored in the repository but not accessible — often because it's scoped to a different environment name than the workflow uses.

**Goal:** Add environment-level secret resolution diagnostics and ensure secrets are stored and referenced with matching environment names.

**Requirements:**
1. Explain the three levels of secrets in GitHub Actions: repository, environment, and organization.
2. Add a diagnostic step that lists all available environment names and checks which secrets each exposes.
3. Verify the `environment:` name in the workflow matches the environment name in GitHub Settings exactly.
4. Show how to promote a repository-level secret to an environment-level secret (or vice versa).
5. Cover the precedence rule: environment-level secrets override repository-level secrets of the same name.
6. Include a checklist for common mismatches: trailing spaces, uppercase vs lowercase, org vs repo.
7. Note that environment secrets are only exposed when the job references that environment — dangling references resolve as undefined.

**Output:** Provide a diagnostic workflow step and a troubleshooting checklist for environment-secret mismatches.
