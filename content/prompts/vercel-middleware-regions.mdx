**Context:** A Next.js project using Middleware (for auth, redirects, A/B testing) fails during the "Deploying outputs" phase when any single Vercel region is unhealthy. Middleware deploys globally by default, making every region a deployment dependency.

**Goal:** Explicitly set the `regions` configuration in `vercel.json` to limit Middleware deployment to healthy regions, and provide a fallback deploy strategy when region outages occur.

**Requirements:**
1. Configure `"regions"` in `vercel.json` to pin deployments to specific regions (e.g., `["iad1", "sfo1"]`) instead of the global default.
2. Explain which features force global deployment: Middleware (`middleware.ts`), Edge Functions, `@vercel/edge`.
3. Provide a diagnostic step to check which regions are currently healthy via Vercel Status API.
4. Cover the trade-off: region pinning reduces deployment surface but may increase latency for users in unpinned regions.
5. Include a CI check that validates the middleware can run without global region dependency.
6. Add a fallback deploy strategy: if the deploy fails with an internal error, check Vercel Status and re-deploy with a reduced region set.
7. Note when you DON'T need Middleware: simple redirects can be done in `next.config.js` redirects, which don't force global deployment.

**Output:** Provide the `vercel.json` region configuration, a health-check script, and a deployment fallback workflow for region outages.
