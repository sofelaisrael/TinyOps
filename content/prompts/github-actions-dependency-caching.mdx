**Context:** GitHub Actions runners are ephemeral — every job starts on a fresh VM with no persisted state. Running `npm install` or `pip install` from scratch on every commit wastes 2-4 minutes per run.

**Goal:** Configure dependency caching for package managers so that subsequent workflow runs skip redundant downloads when the lockfile hasn't changed.

**Requirements:**
1. Use `actions/cache@v4` or `actions/setup-node` built-in caching for Node.js (npm, pnpm, yarn).
2. Set up Docker layer caching using GitHub Actions cache backend (`type=gha`).
3. Include a cache key that auto-invalidates when the lockfile changes via `hashFiles`.
4. Add a `restore-keys` fallback so partial cache hits still speed up installs.
5. Handle pip/poetry caching for Python dependencies if applicable.
6. Output the complete `.github/workflows/ci.yml` with caching integrated into the existing build pipeline.

**Output:** Provide the full YAML workflow file with `actions/cache` steps for each package manager, Docker cache configuration, and notes on cache key strategy.
