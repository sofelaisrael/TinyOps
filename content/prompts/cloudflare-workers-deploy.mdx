**Context:** You develop a Cloudflare Worker locally with `wrangler dev`, but deploying to production requires manual `wrangler deploy` commands. Preview URLs for PRs don't exist.

**Goal:** Create a GitHub Actions workflow that deploys Workers automatically — production on push to main, preview URLs for PRs, with secrets injected from GitHub secrets.

**Requirements:**
1. Install Wrangler in CI: `npm i -g wrangler` or use `cloudflare/wrangler-action@v3`.
2. Configure `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` as repository secrets.
3. Create a `wrangler.toml` with the Worker name, main entry point, and compatibility date.
4. For production deploys (push to `main`): run `wrangler deploy` to publish to the production route.
5. For PR previews: use `wrangler deploy --env preview-{pr-number}` with a separate environment in `wrangler.toml` that has a different route.
6. Map GitHub secrets to Worker secrets using `echo $SECRET | wrangler secret put MY_SECRET` in the workflow.
7. Add a `wrangler.json` or `wrangler.toml` section for `routes`, `triggers`, and `cron` triggers.
8. Create a GitHub Deployment status after deploy so the PR shows a "View Preview" link.
9. Handle `wrangler deploy` failures: check the deployment status via the Cloudflare API and roll back to the previous version if it fails.
10. Use `wrangler versions deploy` and `wrangler versions rollback` for safe rollbacks if using Workers with versioning enabled.

**Output:** Provide a `wrangler.toml` configuration and a GitHub Actions workflow with production deploy + PR previews.
