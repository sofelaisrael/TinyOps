**Context:** Docker builds on GitHub Actions take 15+ minutes because every run starts from scratch — ephemeral runners have no persistent Docker layer cache.

**Goal:** Configure `docker/build-push-action` with GitHub Actions cache (type=gha) so unchanged layers are reused across workflow runs.

**Requirements:**
1. Explain Docker layer caching and why ephemeral runners lose the cache.
2. Use `docker/build-push-action@v6` with `cache-from: type=gha` and `cache-to: type=gha,mode=max`.
3. Show the basic workflow for building and pushing to Docker Hub or GHCR.
4. Cover the `mode=max` vs `mode=min` trade-off — max caches all layers but is slower to save, min caches only exported layers.
5. Include a fallback to registry cache (`type=registry`) for teams that want cache shared across runners.
6. Add cache key scoping by branch and image name to avoid collisions.
7. Note: the GHA cache has a 10GB limit — purge stale caches periodically.

**Output:** Provide a complete Docker build-and-push workflow with layer caching and a comparison of GHA vs registry cache modes.
