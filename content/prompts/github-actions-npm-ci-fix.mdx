**Context:** The `npm ci` step in a GitHub Actions workflow fails with errors like `ERR_PNPM_NO_LOCKFILE`, `EINTEGRITY`, or permission conflicts. Root causes include a missing lockfile, a lockfile out of sync with `package.json`, committed `node_modules`, or a corrupted cache.

**Goal:** Ensure the lockfile is committed, in sync, and valid — and configure the workflow to regenerate it cleanly when necessary.

**Requirements:**
1. Explain that `npm ci` requires an exact `package-lock.json` and fails fast if it's missing or mismatched.
2. Verify the lockfile is committed and not in `.gitignore`.
3. Provide a workflow diagnostic step that checks `package-lock.json` exists and compares its hash against `node_modules/.package-lock.json`.
4. Show how to regenerate a valid lockfile: `rm -rf node_modules package-lock.json && npm install && git add package-lock.json && git commit -m "regenerate lockfile"`.
5. Cover the `EINTEGRITY` error — clear the npm cache and the action cache key.
6. Warn about committed `node_modules` — add it to `.gitignore` and remove from tracking.
7. For pnpm and yarn: note the equivalent lockfile names and commands.

**Output:** Provide a reusable workflow step that validates the lockfile state and regenerates it if needed.
