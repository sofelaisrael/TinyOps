**Context:** I need to run Prisma migrations as part of my production CI/CD pipeline, but I want to avoid downtime when applying schema changes.

**Goal:** Create a robust GitHub Actions workflow that applies Prisma migrations safely, with rollback capabilities and proper error handling.

**Requirements:**
1. Run `prisma migrate deploy` (not `dev`) — only applies pending migrations, never creates new ones.
2. Use `DIRECT_URL` for migrations if using connection poolers like PgBouncer.
3. Generate the Prisma client before deploying the application.
4. Include a pre-flight check (shadow database or `prisma migrate status`) to catch issues early.
5. Add a rollback plan using `prisma migrate resolve` in case of failure.

**Output:** Provide the complete GitHub Action YAML and a shell script for safe migration execution during deployments.
