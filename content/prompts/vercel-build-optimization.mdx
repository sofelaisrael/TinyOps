**Context:** Vercel deployments are slow, fail with generic errors, or the CLI upload stalls at 150MB+. Common causes: `node_modules` getting uploaded, wrong Node version, or custom build commands that conflict with Vercel's install step.

**Goal:** Create a `.vercelignore` and optimized `vercel.json` configuration that reduces upload size, pins the correct Node version, and avoids common build command pitfalls.

**Requirements:**
1. Write a `.vercelignore` that excludes `node_modules`, `.next`, `.git`, `*.md`, test files, and other non-production artifacts from the deployment upload.
2. Pin the Node.js version in `vercel.json` to a version Vercel supports (avoid Node 24 — use `20.x`).
3. Ensure the build command is a single script (`next build` or `vite build`) — NOT `npm i && next build`, since Vercel already runs `npm install` separately.
4. Handle the case where a root-level `api/` directory conflicts with Next.js Pages Router API routes (rename to `_api` or remove).
5. Include a pre-deploy check that runs `next build` locally to catch errors before pushing.
6. Add notes on how to use `vercel deploy --prebuilt --archive=tgz` for very large projects.

**Output:** Provide the `.vercelignore` file, the optimized `vercel.json`, and a pre-flight script that validates the setup.
