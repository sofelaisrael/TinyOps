**Context:** We are terrified of a bad migration corrupting our production data. We want an automated safety net.

**Goal:** Add a step to the deployment workflow that takes a snapshot of our Postgres database (e.g., via `pg_dump` to S3 or a cloud provider's API) before the migration step begins.

**Requirements:**
1. Use `pg_dump` and pipe to AWS S3.
2. Wait for the backup to confirm success before proceeding to `prisma migrate deploy`.
3. Auto-tag the backup with the git commit SHA.

**Output:** Provide the GitHub Action step for the backup.
