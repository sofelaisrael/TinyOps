**Context:** A Personal Access Token (PAT) works perfectly in the browser but `actions/checkout` returns "Not Found" for a private enterprise repo in CI. The PAT has the correct `repo` scope but was never authorized for the SSO-protected organization.

**Goal:** Authorize the PAT for each SSO-protected organization by completing the "Configure SSO" flow in GitHub settings.

**Requirements:**
1. Explain that PATs require explicit SSO authorization per-org, even if they have the correct scopes.
2. Walk through the fix: GitHub → Settings → Developer settings → Personal Access Tokens → Configure SSO → Authorize for each org.
3. For fine-grained PATs: show where to set the "Owner" and resource repository access.
4. Cover how to test the PAT in CI before using it: add a diagnostic step that calls the GitHub API with the token.
5. Show how to verify the PAT's org authorizations using `curl -H "Authorization: Bearer $TOKEN" https://api.github.com/user/orgs`.
6. Warn that expired SAML sessions may cause SSO authorization to drop — tokens may need periodic re-authorization.
7. Include a checklist: check scopes, check SSO, check token expiration, check org membership.

**Output:** Provide a PAT SSO authorization walkthrough and a CI diagnostic step to verify token access to the target org.
