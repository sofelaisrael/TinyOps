**Context:** A Vercel deployment fails with the generic error "Unexpected error. Please try again later" and no build logs. The root cause is an unsupported Node.js version specified in `vercel.json` or `.nvmrc` (e.g., Node 24 before Vercel supports it).

**Goal:** Pin the Node.js version to a known supported release (20.x or 22.x) and verify compatibility before deployment.

**Requirements:**
1. Explain that Vercel supports a specific set of Node.js versions and silently fails on unsupported ones.
2. Set `"node": "20.x"` in the `vercel.json` configuration under the root object.
3. Alternatively: create an `.nvmrc` file with `20` or `22` and Vercel will respect it.
4. Show how to check the current Node version on Vercel: add a build step `node --version` to the logs.
5. Cover the priority order: `vercel.json` overrides `.nvmrc` overrides the project-level `engines` field in `package.json`.
6. Include a CI check that validates the Node version against Vercel's supported matrix before deploying.
7. Warn about major version jumps (Node 22 → 24) that can break `sharp`, `node-gyp`, or native modules.

**Output:** Provide the configuration to pin Node.js version for Vercel and a CI validation step.
