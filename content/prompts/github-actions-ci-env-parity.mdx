**Context:** Tests pass on a local machine but fail in GitHub Actions CI. The discrepancy is caused by environment differences: different Node versions, missing system libraries, case-sensitive filesystem, different timezone, or missing environment variables.

**Goal:** Create a CI configuration that matches the local development environment as closely as possible, and includes diagnostic steps to surface any remaining differences.

**Requirements:**
1. Pin the runner OS version — use `ubuntu-22.04` instead of `ubuntu-latest` to avoid unexpected updates.
2. Pin tool versions explicitly — `actions/setup-node@v4` with `node-version: '20'` instead of relying on the runner default.
3. Print the full CI environment at the start of the workflow (OS, Node, npm, Python, Docker versions).
4. Add a step that checks for missing system dependencies (build-essential, libssl, Python headers) and installs them explicitly.
5. Alert on known differences: CI runs in UTC — ensure tests that depend on timezone are aware.
6. Handle filesystem case sensitivity: macOS is case-insensitive, Linux runners are case-sensitive. Add a lint step for import case mismatches.
7. Provide an `.env.ci` template that mirrors local `.env` with placeholder values for required variables.

**Output:** Provide the complete CI workflow with environment parity checks, pinned tool versions, and a diagnostic summary step.
