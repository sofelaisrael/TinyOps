**Context:** We use Prisma and want to ensure our production database schema hasn't drifted from our migration history before we attempt to deploy new code.

**Goal:** Create a CI step that runs `prisma migrate diff` or `prisma migrate status` to detect if the database schema is out of sync with the migrations folder.

**Requirements:**
1. Spin up a temporary "shadow" database or use the production preview.
2. Fail the CI pipeline if drift is detected.
3. Provide instructions on how the developer should resolve the drift.

**Output:** Provide the GitHub Action step and the Prisma command to use for detection.
