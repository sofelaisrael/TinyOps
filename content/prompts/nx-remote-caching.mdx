**Context:** Every developer on your team runs the same builds locally — wasting compute time. CI also rebuilds everything on every run, even if the code hasn't changed.

**Goal:** Configure Nx Cloud remote caching so build artifacts are shared across all machines — a build done once by any developer or CI runner is reused by everyone else.

**Requirements:**
1. Enable Nx Cloud in `nx.json` by adding `"cloud": { "url": "https://cloud.nx.app" }`.
2. Install the `nx-cloud` package: `npm install -D nx-cloud`.
3. Generate an access token from the Nx Cloud dashboard and store it as `NX_CLOUD_ACCESS_TOKEN` in repository secrets and local `.env.local`.
4. Verify the cache is working: run `npx nx build my-app` twice — the second run should be sub-second.
5. Configure cache read/write permissions in `nx.json` for security: only allow writes from CI, reads from everywhere.
6. Set up a custom cache URL for self-hosted Nx Cloud if you don't want to use the public cloud.
7. Exclude the `.nx/cache` directory from git and add it to `.gitignore`. 
8. Debug cache misses by running `npx nx build my-app --verbose` to see why a cache was invalidated.
9. Handle cache staleness: Nx automatically invalidates the remote cache when inputs change (source files, environment variables, dependencies).
10. Show how to override the cache key for specific tasks using `inputs` in `targetDefaults`.

**Output:** Provide the `nx.json` configuration for remote caching and a verification workflow that confirms cache hits in CI.
