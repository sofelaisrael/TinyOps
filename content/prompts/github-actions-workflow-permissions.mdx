**Context:** GitHub Actions workflows fail with "Resource not accessible by integration" or "Permission to repo.git denied to github-actions[bot]" because the default GITHUB_TOKEN has read-only permissions.

**Goal:** Configure explicit `permissions` blocks at the workflow and job level to grant only the minimum scopes needed for each operation (push, release, PR comments, GHCR, etc.).

**Requirements:**
1. Explain the default GITHUB_TOKEN permission model (read-only on public repos, configurable at org level).
2. Add workflow-level and job-level `permissions:` blocks for the most common operations: `contents: write`, `pull-requests: write`, `packages: write`, `issues: write`.
3. Show the difference between `GITHUB_TOKEN` and a Personal Access Token for cross-repo operations.
4. Include a diagnostic step that dumps the current token's effective permissions.
5. Cover the `workflows` permission — needed when a workflow pushes changes to other workflow files.
6. Provide a decision table: for each operation (create release, push tag, comment PR, push to GHCR, etc.), show which permission is required.

**Output:** Provide a reference template with commented permission blocks and a decision table mapping operations to required scopes.
